# RFD source report (Slide 22)

RFD displays the supplied CSV schema as a raw source report: the same 22 headers, in source order. Dates, decimal text, leading zeros, whitespace, quoted commas/newlines, duplicate rows, blank cells and fully blank 22-cell records remain strings. No stock/quantity calculation or deduplication is inferred. The report is independent of the selected planning file. The live bundle contains no uploaded RFD records.

Admin chooses a UTF-8 CSV on RFD, reviews its explicitly labelled local preview, then presses **Upload & Save**. Upload stages all file rows, including rows outside the current search/page. Only a complete source-order/count audit can activate the new report. Prior completed batches remain stored. Matching chunk retries are idempotent; conflicting retries, foreign owners and partial activation are rejected. After saving, the browser rereads SQL and compares every returned cell with the CSV before claiming a verified save. The original file's SHA-256 is retained in metadata.

The first Admin-requested upload creates only the two fixed RFD tables, `ekwl_rfd_uploads` and `ekwl_rfd_rows`, if missing. This requires the configured database account's normal CREATE privileges. Reads never create schema. An absent installation returns an empty setup state. There is no manual SQL step for ordinary use; setup failures are surfaced without replacing the existing source report. Automatic code deployment itself does not import data or modify SQL schema.

`POST rfd` uses the existing session, CSRF/origin checks, maintenance policy and rate limit. `slide_22` permits reading; writing/setup requires Admin. Stored active reports are global operational source data, matching the other shared report modules, not per-user notes. One repeatable-read transaction validates the active head/counts and streams rows through a single unbuffered cursor. Multiple active heads or incomplete/invalid responses fail closed. Interrupted reads cannot become a successful table. Staged/old inactive batches are excluded from ordinary reads.

The client uses 100-row DOM pages, source-order-preserving search/buyer/place filters, an all-matched-rows CSV export, and at most 60 seconds of in-session reuse. It keeps no report blobs in browser persistence. Owner/generation/token checks and logout clearing prevent late requests or previews from populating another account. First/Last controls expose every row. CSV export reconstructs the same logical header/cell values (quoting/BOM/line endings can differ from original file bytes); filtered files are named as filtered subsets.

Validation includes exact parser/response contracts, synthetic and optional local original-file SQL round trips, source-order/count audits, partial activation, idempotent/conflicting retries, permissions/foreign-owner denial, real page upload/readback, filters, last-page cells, CSV export, planning independence, viewport widths and logout. Private original reports are used only in isolated local tests when explicitly supplied, never committed or included in CI/deployment assets. This preserves source values; it does not certify the factual correctness of the report's business entries or add RFD to forecast calculations.

## Booking tab

Slide 22 also includes Booking, with its own CSV preview, upload, active report, search, buyer/supplier filters and exact-cell CSV export. Its 13 headers match EWO Wise Fabric Booking Information.csv, including the multiline final header. It shares slide_22 read permission and Admin-only writes. Its additive ekwl_rfd_booking_uploads/rows tables are created only on first Admin upload. Saving Booking cannot replace or alter the original RFD report. Both report buffers clear at logout. Neither report is filtered by the selected plan.

## Daily Production Status tab

This replaces the former Daily Cutting Status view with the 25 exact headers of Daily Production Status.csv, including the trailing space in `Cutting Today `. All source cells remain strings; leading zeros, multiline text, blanks, duplicate rows and original row order are preserved in SQL and CSV exports. Buyer → Date → Color cascades alongside text search, content-based auto-fit and 100-row pagination.

The compatible endpoint `rfd/daily-cutting` now reads and writes only `ekwl_rfd_daily_production_uploads` and `ekwl_rfd_daily_production_rows`. An Admin's first Upload & Save creates these independent SQL tables automatically. Uploads stage in bounded chunks; complete row/count audits activate them atomically. The former 14-column source is neither displayed nor used by Fabrics Details, and its header is rejected. Existing historical tables are left untouched; no production data is deleted by deployment. RFD and Booking stay independent. Private CSV contents are not shipped in public code.

Footer daily measures (Cutting/Sewing/Finishing Receive/Iron/Hang Tag/Folding/Poly/Carton Today/day) sum once per EWO + Color + source date. Order Qty, cumulative Total columns and Carton WIP use each pair's newest date within the current filter. Repeated equal values count once; conflicting or missing latest values are unavailable and never fall back to earlier dates. Invalid dates block a pair's cumulative subtotal. Partial subtotals are marked. All production quantities use PCS; identifiers and text are not added. Source exports retain every original filtered row, including duplicates, and do not include artificial subtotal records.

## Fabrics Details Report

The fourth tab is derived from completed RFD, Booking and Daily Cutting reports plus active Embellishment and Sewing reports. The supplied file contains the 31 output headers only; it is not uploaded as data. Grain is EWO + Color + Construction + Composition. Booking quantity is per grain; Total Booking, textile receipt, order quantity, consumption, cuttable pieces and production/WIP are EWO+Color measures repeated across fabric rows, never additive across those rows. Units must match before adding or dividing.

Consumption = Total Booking / unique Total Order Qty, rounded to eight decimals. Cuttable pieces = total textile receipt in the same unit / consumption. Received for Cutting is explicitly excluded from every calculation by the latest user instruction. MCD Live Stock remains unavailable until a replacement formula is supplied. Cutting Total and Order Qty use the latest Daily Production date per EWO+Color. Missing/conflicting latest values or unrecognized dates remain unavailable, with source date/row references in evidence. Earlier cumulative dates are never added. Daily Production Sewing Total is output, so it does not replace the existing Sewing Input/WIP report. Sewing uses the active whole-report head and sums all lines; embellishment sums active daily movements, not cumulative total columns. The latest completed plan supplies process applicability only; it does not filter report rows. No unambiguous matching plan means Cutting WIP remains unavailable rather than inferring no-process from zero movements. Both Print and Embroidery present means Cutting WIP is unresolved until final routing is known. No matching source is unavailable rather than zero.

The endpoint reads sources in a repeatable-read SQL transaction. Admin refresh creates/updates two additive SQL materialization tables with model version, exact dependency digest and evidence. A cached result is never substituted for changed source data. Read-only users can calculate without writes. All cells expose scope, formula and source row references. Source heads/counts and all row receipts are checked before use; incomplete or ambiguous inputs fail closed.

Fabric Details uses an explicit RFD-only index on EWO, Color, Fabric Construction and Fabric Composition. All four normalized keys must match. All distinct nonblank matching RFD descriptions are displayed, separated by newlines; a valid multiple-value source is not discarded as a conflict. No-match and matched-but-blank outcomes have separate evidence, including the requested keys and candidate row counts at each matching level. Model version v4 also includes approved color mappings and the Order Bank reference version in its dependency digest.

## Cascading filters and quantity totals

Each tab has a Color filter. Choices cascade from Buyer to Place/Supplier/Date (where present) to Color; global search also narrows choices. Changing an upstream choice clears only incompatible downstream selections. Filters match case/whitespace-insensitively while preserving original row text/order and export values.

Sticky footer totals cover every matching row, not just the current page. Only additive quantities are summed: identifiers, GSM/width dimensions and consumption rates are not added. Exact BigInt arithmetic retains up to eight decimal places; units remain separate. Missing or conflicting data yields —, or an explicitly marked available subtotal (*), never an assumed zero. Daily Production Today quantities count once per pair/date; cumulative Total, Order and Carton WIP quantities use the latest selected pair date. Received for Cutting remains excluded. Fabrics Details EWO+Color measures count once per pair despite repeated fabric rows; MCD remains blank. Source exports stay source rows only, with no artificial total records. Filtering/totals do not mutate SQL or uploaded records. View caches and dropdown values are cleared on logout.

Table sizing measures the filtered source text, header labels and footer values. Short columns remain compact; longer text columns expand within readable caps and wrap with automatic row height. Sticky offsets follow the measured first columns. The scroll area uses the remaining viewport height and stays naturally short for small datasets. Width and total caches make pagination reuse the filtered calculation; caches clear on source/session reset.

## EWO display and original-value hover

All four table views display the distinct six-digit numeric codes found in their EWO source cell, retaining leading zeros and showing multiple codes on separate lines. No rows are merged, filtered out or deleted by formatting. Only changed displays have an original-value tooltip, available on mouse hover and keyboard focus, with exact source text inserted safely as text. A portal tooltip stays outside the table scroll clipping and clears on rerender, scroll, resize, Escape and session reset.

This is presentation only: SQL values, matching keys, quantity calculations, search and source exports retain their existing exact original values. Identifiers without a complete six-digit code remain visible unchanged rather than being truncated, padded or silently discarded. Column auto-fit measures displayed EWO text.

Booking No uses the same six-digit presentation as EWO No, with an explicitly labelled Original Booking No tooltip. FBR and Add suffixes stay in SQL, search, calculations and CSV exports. Multiple booking rows with the same displayed number remain independent; booking quantities are not merged or deduplicated by their display text. Auto-fit measures the short Booking No display.

## Data Converter: EWO–Color review

The fifth tab reads current complete RFD, Booking, Daily Production and Order Bank source identities in one repeatable-read SQL snapshot. There are no quantity fields in the comparison payload or UI. Original EWO/Color, RFD Fabric Details, RFD/Booking Construction and Composition, source heads and source row references remain inspectable. Fields not supplied by a source remain Not available.

A clean EWO key is used only when exactly one distinct six-digit identifier is present; ambiguous/missing EWO records remain separate issues. Color equality normalizes case and whitespace only. An EWO's color group is hidden only when it is present in all four sources. Each unmatched EWO lists only incomplete color groups; Review also includes matched reference colors for that EWO, without pairing unrelated candidates or exposing quantities. Missing source rows, missing colors, ambiguous identities and multiple targets require review. No fuzzy color or fabric match is auto-approved, and no row is deleted by comparison.

Only an Admin with slide_22 access can approve a source-specific color alias, with explicit confirmation and a source-version digest. The target must exist in current Order Bank colors for the same EWO. Distinct existing Order Bank colors cannot be merged. A stale source/approval digest returns 409. The first Admin approval creates the additive ekwl_rfd_color_mappings table; read-only requests create nothing. Approval/revocation writes mapping records and audit history including source versions; uploaded source cells are never updated. A mapping whose source alias or Order Bank target disappears becomes inactive for matching until reviewed. Admins can revoke a mapping; readers can inspect but cannot approve or revoke.

Fabrics Details model v4 includes approved effective mappings and their provenance in its dependency digest/evidence. With no active mappings, FDR avoids an unnecessary Order Bank scan; Data Converter always checks all four identity sources. Only EWO/color grouping changes; fabric identity still requires Construction and Composition. Formulas, units, missing-data guards, source aggregation and process routing rules remain unchanged. Approvals invalidate the current browser's FDR result and late requests cannot restore old account data. Operational Sewing/Embellishment/plan colors retain their own existing exact matching; no aliases are inferred for sources outside the four reviewed reports. Received for Cutting remains excluded and MCD remains unavailable pending a formula.
