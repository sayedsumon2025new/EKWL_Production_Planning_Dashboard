# RFD source report (Slide 22)

RFD displays the supplied CSV schema as a raw source report: the same 22 headers, in source order. Dates, decimal text, leading zeros, whitespace, quoted commas/newlines, duplicate rows, blank cells and fully blank 22-cell records remain strings. No stock/quantity calculation or deduplication is inferred. The report is independent of the selected planning file. The live bundle contains no uploaded RFD records.

Admin chooses a UTF-8 CSV on RFD, reviews its explicitly labelled local preview, then presses **Upload & Save**. Upload stages all file rows, including rows outside the current search/page. Only a complete source-order/count audit can activate the new report. Prior completed batches remain stored. Matching chunk retries are idempotent; conflicting retries, foreign owners and partial activation are rejected. After saving, the browser rereads SQL and compares every returned cell with the CSV before claiming a verified save. The original file's SHA-256 is retained in metadata.

The first Admin-requested upload creates only the two fixed RFD tables, `ekwl_rfd_uploads` and `ekwl_rfd_rows`, if missing. This requires the configured database account's normal CREATE privileges. Reads never create schema. An absent installation returns an empty setup state. There is no manual SQL step for ordinary use; setup failures are surfaced without replacing the existing source report. Automatic code deployment itself does not import data or modify SQL schema.

`POST rfd` uses the existing session, CSRF/origin checks, maintenance policy and rate limit. `slide_22` permits reading; writing/setup requires Admin. Stored active reports are global operational source data, matching the other shared report modules, not per-user notes. One repeatable-read transaction validates the active head/counts and streams rows through a single unbuffered cursor. Multiple active heads or incomplete/invalid responses fail closed. Interrupted reads cannot become a successful table. Staged/old inactive batches are excluded from ordinary reads.

The client uses 100-row DOM pages, source-order-preserving search/buyer/place filters, an all-matched-rows CSV export, and at most 60 seconds of in-session reuse. It keeps no report blobs in browser persistence. Owner/generation/token checks and logout clearing prevent late requests or previews from populating another account. First/Last controls expose every row. CSV export reconstructs the same logical header/cell values (quoting/BOM/line endings can differ from original file bytes); filtered files are named as filtered subsets.

Validation includes exact parser/response contracts, synthetic and optional local original-file SQL round trips, source-order/count audits, partial activation, idempotent/conflicting retries, permissions/foreign-owner denial, real page upload/readback, filters, last-page cells, CSV export, planning independence, viewport widths and logout. Private original reports are used only in isolated local tests when explicitly supplied, never committed or included in CI/deployment assets. This preserves source values; it does not certify the factual correctness of the report's business entries or add RFD to forecast calculations.
